ผ# ผลการดำเนินงานในโครงงาน Speech-to-Text

บทนี้จะกล่าวถึงผลการดำเนินงานได้แก่ การพัฒนาเว็บ Interface ของระบบ Speech-to-Text โดยใช้ Streamlit Framework เพื่อสร้าง Web Application ที่มี User Interface ที่ใช้งานง่ายและรองรับการใช้งานบนหลายแพลตฟอร์ม รวมถึงการแยกโครงสร้างโปรเจกต์เป็น Backend และ Frontend เพื่อให้ง่ายต่อการดูแลรักษาและขยายความสามารถในอนาคต

## 1. การพัฒนาเว็บ Interface

### 1.1 การใช้ Streamlit Framework

ได้มีการพัฒนาเว็บ Interface โดยใช้ Streamlit Framework ซึ่งเป็น Python-based Web Framework ที่เหมาะสำหรับการสร้าง Data Science Applications และ Machine Learning Applications โดยมีข้อดีคือสามารถสร้าง Web Application ได้อย่างรวดเร็วโดยไม่ต้องเขียน HTML, CSS หรือ JavaScript โดยตรง

### 1.2 ส่วนประกอบของ Interface

ระบบมีส่วนประกอบหลักดังนี้:

- **Sidebar Component**: แสดงสถานะการโหลดโมเดล, การตั้งค่าเสียง, และปุ่มสำหรับจัดการประวัติการถอดเสียง
- **Recording Component**: ส่วนสำหรับบันทึกเสียงแบบ Real-time และอัปโหลดไฟล์เสียง
- **Results Component**: แสดงประวัติการถอดเสียงทั้งหมดในรูปแบบ Expandable Sections พร้อมปุ่มคัดลอกผลลัพธ์
- **Audio Settings Component**: การเลือกไมโครโฟน, ตั้งค่า Sample Rate, Channels, และ Chunk Size

### 1.3 การออกแบบ UI/UX

ได้มีการออกแบบ User Interface ให้ใช้งานง่ายและสวยงาม โดยมีคุณสมบัติดังนี้:

- ปุ่มบันทึกเสียงขนาดใหญ่ที่อยู่ตรงกลางหน้าจอ เพื่อให้สะดวกต่อการใช้งาน
- แสดงระยะเวลาการบันทึกแบบ Real-time เพื่อให้ผู้ใช้ทราบสถานะการบันทึก
- Preview เสียงที่บันทึกได้ก่อนการถอดเสียง เพื่อให้ผู้ใช้สามารถตรวจสอบคุณภาพเสียงได้
- Loading Indicators และ Progress Bars เพื่อแสดงสถานะการโหลดโมเดลและการประมวลผล
- รองรับการอัปโหลดหลายไฟล์พร้อมกัน พร้อมแสดง Progress Bar

## 2. โครงสร้างโปรเจกต์

### 2.1 การแยก Backend และ Frontend

ได้มีการแยกโครงสร้างโปรเจกต์ออกเป็น Backend และ Frontend อย่างชัดเจน เพื่อให้ง่ายต่อการดูแลรักษาและขยายความสามารถในอนาคต

#### 2.1.1 Backend (`app/backend/`)

Backend รับผิดชอบการจัดการ Business Logic, Models, และ Services ประกอบด้วย:

- **Configuration (`config.py`)**: เก็บการตั้งค่าต่างๆ ของแอปพลิเคชัน เช่น path ของโมเดล, device configuration, audio settings
- **Models (`models/asr_model.py`)**: Class `TyphoonASRRecognizer` สำหรับจัดการโมเดล ASR โดยมี method `load_model()` สำหรับโหลดโมเดลจากไฟล์ `.nemo` และ `transcribe_audio()` สำหรับถอดเสียงจากไฟล์เสียง
- **Services (`services/audio_service.py`)**: 
  - Class `AudioRecorder` สำหรับบันทึกเสียงแบบ Real-time ด้วย PyAudio
  - Class `AudioDeviceManager` สำหรับจัดการ audio input devices

#### 2.1.2 Frontend (`app/frontend/`)

Frontend รับผิดชอบการแสดงผล UI และการโต้ตอบกับผู้ใช้ ประกอบด้วย:

- **Main App (`streamlit_app.py`)**: Entry point ของ Streamlit application ที่จัดการ session state และรวม components ทั้งหมดเข้าด้วยกัน
- **Styles (`styles.py`)**: เก็บ CSS styles สำหรับ UI
- **Components (`components/`)**: UI components ที่แยกตามหน้าที่ ได้แก่ `sidebar.py`, `recording.py`, `results.py`, และ `audio_settings.py`

### 2.2 ข้อดีของการแยกโครงสร้าง

การแยกโครงสร้างนี้มีข้อดีดังนี้:

- **Separation of Concerns**: Backend และ Frontend แยกกันชัดเจน ทำให้ง่ายต่อการดูแลรักษา
- **Modularity**: แต่ละ component มีหน้าที่ชัดเจน สามารถนำไปใช้ซ้ำได้
- **Maintainability**: โครงสร้างชัดเจน ง่ายต่อการดูแลรักษาและแก้ไข
- **Scalability**: สามารถขยายความสามารถได้ง่ายโดยการเพิ่ม component หรือ service ใหม่

## 3. ระบบบันทึกเสียง

### 3.1 การใช้ PyAudio

ได้มีการใช้ PyAudio Library สำหรับการบันทึกเสียงจากไมโครโฟนแบบ Real-time โดยมีคุณสมบัติดังนี้:

- **Real-time Recording**: บันทึกเสียงผ่านไมโครโฟนด้วย PyAudio ใน thread แยก เพื่อไม่ให้บล็อก UI
- **Device Selection**: รองรับการเลือกไมโครโฟนที่ต้องการใช้
- **Audio Settings**: รองรับการตั้งค่า Sample Rate, Channels, และ Chunk Size
- **Duration Display**: แสดงระยะเวลาการบันทึกแบบ Real-time
- **Audio Preview**: ฟังเสียงที่บันทึกได้ก่อนการถอดเสียง

### 3.2 การบันทึกเสียง

Class `AudioRecorder` มี method หลักดังนี้:

- `start_recording()`: เริ่มบันทึกเสียงจากไมโครโฟนด้วย PyAudio
- `stop_recording()`: หยุดบันทึกและบันทึกเป็นไฟล์ WAV
- `get_duration()`: คำนวณระยะเวลาการบันทึก
- `get_audio_bytes()`: ได้ audio bytes สำหรับ preview

### 3.3 การจัดการ Audio Devices

Class `AudioDeviceManager` มี method สำหรับจัดการ audio input devices:

- `get_input_devices()`: ดึงรายการ input devices ทั้งหมด
- `get_microphone_devices()`: ดึงรายการไมโครโฟนเท่านั้น

## 4. หน้าจอแสดงผลของเว็บแอปพลิเคชัน (Web Application)

### 4.1 หน้าต่างแสดงหน้าแรกของเว็บแอปพลิเคชัน

หน้าต่างแสดงหน้าแรกของเว็บแอปพลิเคชัน Speech-to-Text โดยมีการแสดงหัวข้อหลักของระบบ "🎤 Speech-to-Text with Typhoon ASR Real-time" เพื่อให้ผู้ใช้งานเข้าใจว่าระบบนี้เป็นระบบสำหรับแปลงเสียงพูดเป็นข้อความด้วยเทคโนโลยี Typhoon ASR Real-time ซึ่งเป็นโมเดลสำหรับถอดเสียงภาษาไทยที่มีความแม่นยำสูง

หน้าแรกของเว็บแอปพลิเคชันจะมีการแสดงสถานะการโหลดโมเดล โดยระบบจะทำการโหลดโมเดล Typhoon ASR อัตโนมัติเมื่อเปิดแอปพลิเคชันครั้งแรก ซึ่งจะแสดงข้อความ "🔄 กำลังโหลดโมเดล Typhoon ASR จากไฟล์ local..." และ "⏳ กรุณารอสักครู่ (อาจใช้เวลา 1-2 นาที)" เพื่อแจ้งให้ผู้ใช้ทราบว่าระบบกำลังโหลดโมเดลอยู่

**รูปที่ 4.1 หน้าต่างแรก (Home Page) เพื่อเริ่มการใช้งาน**

เมื่อระบบโหลดโมเดลเสร็จสิ้น จะแสดงข้อความ "✅ โมเดล Typhoon ASR โหลดเสร็จสิ้น!" พร้อมกับแสดงลูกบอลลูนเพื่อแสดงความสำเร็จ และระบบจะพร้อมใช้งานทันที โดยผู้ใช้ไม่จำเป็นต้องกดปุ่มโหลดโมเดลเอง เนื่องจากระบบจะโหลดอัตโนมัติ

### 4.2 หน้าต่าง Sidebar สำหรับการตั้งค่าและสถานะโมเดล

ทางเว็บแอปพลิเคชันได้มี Sidebar ด้านซ้ายของหน้าจอ ซึ่งแสดงข้อมูลสำคัญต่างๆ ดังนี้:

- **สถานะโมเดล**: แสดงสถานะการโหลดโมเดล ASR โดยจะแสดง "✅ ASR พร้อมใช้งาน" เมื่อโมเดลโหลดเสร็จสิ้น พร้อมแสดงชื่อไฟล์โมเดลที่โหลดมา และข้อความ "✅ โมเดลพร้อมใช้งาน - สามารถถอดเสียงได้เลย"
- **ปุ่มโหลดโมเดลใหม่**: มีปุ่ม "🔄 โหลดโมเดลใหม่" สำหรับโหลดโมเดลใหม่ในกรณีที่เกิดปัญหา
- **การตั้งค่าเสียง**: มีส่วนสำหรับการตั้งค่าเสียงต่างๆ เช่น การเลือกไมโครโฟน, Sample Rate, Channels, และ Chunk Size
- **ปุ่มล้างประวัติ**: มีปุ่ม "🗑️ ล้างประวัติ" สำหรับล้างประวัติการถอดเสียงทั้งหมด

**รูปที่ 4.2 หน้าต่าง Sidebar แสดงสถานะโมเดลและการตั้งค่า**

### 4.3 หน้าต่างการบันทึกเสียง (Recording Section)

หน้าต่างการบันทึกเสียงเป็นส่วนหลักของแอปพลิเคชัน โดยมีคุณสมบัติดังนี้:

- **ปุ่มบันทึกเสียงขนาดใหญ่**: มีปุ่มบันทึกเสียงขนาดใหญ่ที่อยู่ตรงกลางหน้าจอ โดยปุ่มจะแสดง "🔴 เริ่มบันทึก" เมื่อยังไม่ได้บันทึก และจะเปลี่ยนเป็น "⏹️ หยุดบันทึก" เมื่อกำลังบันทึกเสียงอยู่
- **แสดงระยะเวลาการบันทึก**: แสดงระยะเวลาการบันทึกแบบ Real-time ในรูปแบบ "⏱️ ระยะเวลา: X.X วินาที" เพื่อให้ผู้ใช้ทราบระยะเวลาที่บันทึกไปแล้ว
- **Preview เสียง**: หลังจากหยุดบันทึก จะแสดงส่วน Preview เสียงที่บันทึกได้ เพื่อให้ผู้ใช้สามารถฟังเสียงก่อนการถอดเสียงได้
- **การถอดเสียงอัตโนมัติ**: เมื่อหยุดบันทึกเสียง ระบบจะทำการถอดเสียงอัตโนมัติและแสดงผลลัพธ์ทันที

**รูปที่ 4.3 หน้าต่างการบันทึกเสียงพร้อมปุ่มบันทึกขนาดใหญ่**

### 4.4 หน้าต่างการตั้งค่าเสียง (Audio Settings)

หน้าต่างการตั้งค่าเสียงอยู่ใน Sidebar โดยมีส่วนประกอบดังนี้:

- **การเลือกไมโครโฟน**: มี dropdown สำหรับเลือกไมโครโฟนที่ต้องการใช้ โดยระบบจะสแกนและแสดงรายการไมโครโฟนทั้งหมดที่เชื่อมต่อกับเครื่อง
- **Sample Rate**: มี dropdown สำหรับเลือก Sample Rate (เช่น 8000, 16000, 32000, 44100, 48000 Hz) โดยค่าเริ่มต้นคือ 16000 Hz
- **Channels**: มี dropdown สำหรับเลือกจำนวนช่องสัญญาณเสียง (Mono หรือ Stereo) โดยค่าเริ่มต้นคือ Mono (1 channel)
- **Chunk Size**: มี dropdown สำหรับเลือก Chunk Size สำหรับการบันทึกเสียง โดยค่าเริ่มต้นคือ 1024

การตั้งค่าเหล่านี้จะถูกบันทึกใน Session State และจะถูกใช้เมื่อเริ่มบันทึกเสียงครั้งถัดไป

**รูปที่ 4.4 หน้าต่างการตั้งค่าเสียงใน Sidebar**

### 4.5 หน้าต่างการอัปโหลดไฟล์เสียง (File Upload)

หน้าต่างการอัปโหลดไฟล์เสียงอยู่ด้านล่างของส่วนบันทึกเสียง โดยมีคุณสมบัติดังนี้:

- **File Uploader**: มี file uploader ที่รองรับการอัปโหลดหลายไฟล์พร้อมกัน โดยรองรับไฟล์เสียงหลายรูปแบบ ได้แก่ WAV, MP3, M4A, และ FLAC
- **แสดงจำนวนไฟล์**: เมื่อเลือกไฟล์แล้ว จะแสดงข้อความ "📂 เลือกไฟล์แล้ว X ไฟล์" พร้อมแสดงชื่อไฟล์และขนาดไฟล์
- **ปุ่มถอดเสียงจากไฟล์ทั้งหมด**: มีปุ่ม "🎵 ถอดเสียงจากไฟล์ทั้งหมด" สำหรับเริ่มการถอดเสียงจากไฟล์ที่อัปโหลดมา
- **Progress Bar**: ขณะประมวลผล จะแสดง Progress Bar และข้อความแสดงไฟล์ที่กำลังประมวลผล
- **Summary**: หลังจากประมวลผลเสร็จ จะแสดงสรุปจำนวนไฟล์ที่สำเร็จและไม่สำเร็จ

**รูปที่ 4.5 หน้าต่างการอัปโหลดไฟล์เสียง**

### 4.6 หน้าต่างผลลัพธ์การถอดเสียง (Results Section)

หน้าต่างผลลัพธ์การถอดเสียงอยู่ด้านขวาของหน้าจอ โดยมีคุณสมบัติดังนี้:

- **แสดงประวัติการถอดเสียง**: แสดงประวัติการถอดเสียงทั้งหมดในรูปแบบ Expandable Sections โดยเรียงลำดับจากใหม่ไปเก่า
- **ข้อมูลในแต่ละรายการ**: แต่ละรายการจะแสดง:
  - **หัวข้อ**: แสดงชื่อไฟล์ (ถ้าเป็นไฟล์ที่อัปโหลด) หรือ "🎙️ บันทึกเสียง" (ถ้าเป็นเสียงที่บันทึก) พร้อมเวลา
  - **ข้อความที่ถอดได้**: แสดงข้อความที่ถอดเสียงได้
  - **ปุ่มคัดลอก**: มีปุ่ม "📋 คัดลอก" สำหรับคัดลอกข้อความที่ถอดเสียงได้
- **Expanded by Default**: รายการล่าสุดจะถูกขยายโดยอัตโนมัติเพื่อให้ผู้ใช้เห็นผลลัพธ์ล่าสุดทันที
- **ข้อความเมื่อยังไม่มีผลลัพธ์**: แสดงข้อความ "ยังไม่มีผลลัพธ์การถอดเสียง" เมื่อยังไม่มีการถอดเสียง

**รูปที่ 4.6 หน้าต่างผลลัพธ์การถอดเสียง**

### 4.7 หน้าต่างแสดงสถานะการโหลดโมเดล

เมื่อเปิดแอปพลิเคชันครั้งแรก หรือเมื่อกดปุ่ม "🔄 โหลดโมเดลใหม่" ระบบจะแสดงหน้าต่างการโหลดโมเดล โดยมีส่วนประกอบดังนี้:

- **ข้อความแจ้งเตือน**: แสดงข้อความ "🔄 กำลังโหลดโมเดล Typhoon ASR จากไฟล์ local..." และ "⏳ กรุณารอสักครู่ (อาจใช้เวลา 1-2 นาที)"
- **Loading Spinner**: แสดง spinner พร้อมข้อความ "📂 กำลังอ่านและโหลดโมเดล..." เพื่อแสดงว่าระบบกำลังทำงาน
- **ข้อความสำเร็จ**: เมื่อโหลดเสร็จสิ้น จะแสดงข้อความ "✅ โมเดล Typhoon ASR โหลดเสร็จสิ้น!" พร้อมกับแสดงลูกบอลลูน
- **ข้อความข้อผิดพลาด**: หากเกิดข้อผิดพลาด จะแสดงข้อความแจ้งเตือนพร้อมคำแนะนำในการแก้ไข

## 5. การใช้โมเดล ASR

### 5.1 Typhoon ASR Model

ได้มีการใช้ Typhoon ASR (Automatic Speech Recognition) Model ซึ่งเป็นโมเดลสำหรับถอดเสียงภาษาไทย โดยมีคุณสมบัติดังนี้:

- **Local Model Loading**: โหลดโมเดลจากไฟล์ `.nemo` ในเครื่อง ไม่ต้องพึ่งพา API
- **Automatic Loading**: โหลดโมเดลอัตโนมัติเมื่อเปิดแอปพลิเคชัน
- **Fallback Mechanism**: มี fallback ไปใช้ `typhoon-asr` package ถ้า NeMo ไม่สามารถใช้งานได้

### 5.2 การถอดเสียง

Class `TyphoonASRRecognizer` มี method หลักดังนี้:

- `load_model()`: โหลดโมเดลจากไฟล์ `.nemo` โดยใช้ NeMo Toolkit หรือ fallback ไปใช้ `typhoon-asr` package
- `transcribe_audio()`: ถอดเสียงจากไฟล์เสียง โดยรองรับทั้ง Hypothesis objects และ strings จาก NeMo

### 5.3 การจัดการผลลัพธ์

ได้มีการจัดการผลลัพธ์จากโมเดล ASR อย่างถูกต้อง โดยรองรับทั้ง:

- Hypothesis objects จาก NeMo (มี attribute `text` หรือ `transcript`)
- Strings โดยตรง
- Lists ของ transcripts

## 6. การรองรับไฟล์เสียง

### 6.1 รูปแบบไฟล์ที่รองรับ

ระบบรองรับไฟล์เสียงหลายรูปแบบ ได้แก่:

- WAV (Waveform Audio File Format)
- MP3 (MPEG Audio Layer III)
- M4A (MPEG-4 Audio)
- FLAC (Free Lossless Audio Codec)

### 6.2 การประมวลผลหลายไฟล์

ระบบรองรับการอัปโหลดและประมวลผลหลายไฟล์พร้อมกัน โดยมีคุณสมบัติดังนี้:

- Progress Bar แสดงความคืบหน้าการประมวลผล
- Status Text แสดงไฟล์ที่กำลังประมวลผล
- Summary แสดงจำนวนไฟล์ที่สำเร็จและไม่สำเร็จ

## 7. การทดสอบและผลลัพธ์

### 7.1 การทดสอบระบบ

ได้มีการทดสอบระบบในหลายด้านดังนี้:

- **การบันทึกเสียง**: ทดสอบการบันทึกเสียงจากไมโครโฟนแบบ Real-time
- **การถอดเสียง**: ทดสอบการถอดเสียงจากไฟล์เสียงที่บันทึกและไฟล์ที่อัปโหลด
- **การเลือกอุปกรณ์**: ทดสอบการเลือกไมโครโฟนที่แตกต่างกัน
- **การตั้งค่าเสียง**: ทดสอบการตั้งค่า Sample Rate, Channels, และ Chunk Size ที่แตกต่างกัน
- **การประมวลผลหลายไฟล์**: ทดสอบการอัปโหลดและประมวลผลหลายไฟล์พร้อมกัน

### 7.2 ผลลัพธ์การทดสอบ

ผลการทดสอบพบว่า:

- ระบบสามารถบันทึกเสียงจากไมโครโฟนได้อย่างถูกต้อง
- ระบบสามารถถอดเสียงจากไฟล์เสียงที่บันทึกและไฟล์ที่อัปโหลดได้อย่างถูกต้อง
- ระบบสามารถเลือกไมโครโฟนที่ต้องการใช้ได้
- ระบบสามารถตั้งค่าเสียงได้ตามต้องการ
- ระบบสามารถประมวลผลหลายไฟล์พร้อมกันได้
- ระบบแสดงผลลัพธ์การถอดเสียงได้อย่างถูกต้องและสวยงาม

### 7.3 ข้อจำกัดและปัญหา

พบข้อจำกัดและปัญหาดังนี้:

- **Hypothesis Object Handling**: ในตอนแรกพบปัญหาว่า NeMo คืนค่า Hypothesis object แทน string ทำให้เกิด error `'Hypothesis' object has no attribute 'strip'` ซึ่งได้แก้ไขโดยการตรวจสอบและดึง text จาก Hypothesis object อย่างถูกต้อง
- **Model Loading Time**: การโหลดโมเดลใช้เวลาพอสมควร ขึ้นอยู่กับขนาดของโมเดลและประสิทธิภาพของเครื่อง
- **Audio Format Support**: ระบบรองรับไฟล์เสียงหลายรูปแบบ แต่การแปลงไฟล์บางรูปแบบอาจใช้เวลาพอสมควร

**อาการ**: ไม่สามารถรันโปรแกรมได้ หรือแสดง error เกี่ยวกับ Streamlit

**วิธีแก้ไข**:
1. ติดตั้ง Streamlit ใหม่:
   ```
   pip install streamlit
   ```
2. ตรวจสอบว่า Python ถูกติดตั้งและอยู่ใน PATH
3. ลองรันคำสั่ง:
   ```
   streamlit --version
   ```
   เพื่อตรวจสอบว่า Streamlit ติดตั้งสำเร็จ

#### ข.5 ปัญหา: Error 'Hypothesis' object has no attribute 'strip'

**อาการ**: แสดงข้อความ "เกิดข้อผิดพลาดในการถอดเสียง: 'Hypothesis' object has no attribute 'strip'"

**วิธีแก้ไข**:
1. ปัญหานี้ได้รับการแก้ไขแล้วในโค้ดปัจจุบัน
2. หากยังพบปัญหา ให้ตรวจสอบว่าใช้เวอร์ชันล่าสุดของโค้ด
3. หรืออัปเดต NeMo Toolkit:
   ```
   pip install --upgrade nemo_toolkit[asr]
   ```

### ภาคผนวก ค. ตัวอย่างการใช้งาน

#### ค.1 ตัวอย่างการบันทึกเสียงและถอดเสียง

1. เปิดแอปพลิเคชัน Speech-to-Text

2. รอให้ระบบโหลดโมเดลเสร็จสิ้น (แสดง "✅ ASR พร้อมใช้งาน")

3. กดปุ่ม "🔴 เริ่มบันทึก"

4. พูดประโยคที่ต้องการ เช่น "สวัสดีครับ วันนี้เป็นวันที่ดีมาก"

5. กดปุ่ม "⏹️ หยุดบันทึก"

6. ระบบจะแสดงผลลัพธ์การถอดเสียงในส่วน "📝 ผลลัพธ์"

**รูปที่ ค.1 ตัวอย่างการบันทึกเสียงและผลลัพธ์**

#### ค.2 ตัวอย่างการอัปโหลดไฟล์เสียง

1. เลื่อนลงไปที่ส่วน "📁 อัปโหลดไฟล์เสียง"

2. กดปุ่ม "Browse files" และเลือกไฟล์เสียงที่ต้องการ (สามารถเลือกหลายไฟล์ได้)

3. ระบบจะแสดงจำนวนไฟล์ที่เลือก เช่น "📂 เลือกไฟล์แล้ว 3 ไฟล์"

4. กดปุ่ม "🎵 ถอดเสียงจากไฟล์ทั้งหมด"

5. ระบบจะแสดง Progress Bar และประมวลผลไฟล์ทีละไฟล์

6. หลังจากเสร็จสิ้น ระบบจะแสดงสรุปจำนวนไฟล์ที่สำเร็จและไม่สำเร็จ

**รูปที่ ค.2 ตัวอย่างการอัปโหลดไฟล์เสียง**

#### ค.3 ตัวอย่างการดูประวัติการถอดเสียง

1. ไปที่ส่วน "📝 ผลลัพธ์" ด้านขวาของหน้าจอ

2. จะเห็นรายการประวัติการถอดเสียงทั้งหมด เรียงลำดับจากใหม่ไปเก่า

3. แต่ละรายการจะแสดง:
   - ชื่อไฟล์หรือ "🎙️ บันทึกเสียง" พร้อมเวลา
   - ข้อความที่ถอดเสียงได้
   - ปุ่ม "📋 คัดลอก" สำหรับคัดลอกข้อความ

4. กดที่รายการเพื่อขยายและดูรายละเอียด

**รูปที่ ค.3 ตัวอย่างประวัติการถอดเสียง**

### ภาคผนวก ง. รายการ Dependencies และเวอร์ชัน

#### ง.1 Python Dependencies

โปรแกรมใช้ Python libraries ต่อไปนี้:

- **streamlit**: เวอร์ชัน 1.28.0 หรือสูงกว่า - สำหรับ Web UI Framework
- **nemo_toolkit[asr]**: เวอร์ชัน 1.20.0 หรือสูงกว่า - สำหรับ ASR Model (แนะนำ)
- **typhoon-asr**: เวอร์ชันล่าสุด - สำหรับ ASR Model (fallback)
- **pyaudio**: เวอร์ชัน 0.2.11 หรือสูงกว่า - สำหรับการบันทึกเสียง
- **soundfile**: เวอร์ชัน 0.12.1 หรือสูงกว่า - สำหรับจัดการไฟล์เสียง
- **numpy**: เวอร์ชัน 1.24.0 หรือสูงกว่า - สำหรับการประมวลผลข้อมูล

#### ง.2 ระบบปฏิบัติการที่รองรับ

- **Windows**: Windows 10 หรือสูงกว่า
- **macOS**: macOS 10.14 หรือสูงกว่า
- **Linux**: Ubuntu 18.04 หรือสูงกว่า, หรือ Linux distributions อื่นๆ ที่รองรับ Python

#### ง.3 ข้อกำหนดของระบบ

- **Python**: เวอร์ชัน 3.8 หรือสูงกว่า

- **Storage**: อย่างน้อย 2 GB สำหรับโมเดลและ dependencies
- **Audio Device**: ไมโครโฟนสำหรับการบันทึกเสียง
