# PharmaLog AI Lab — Benchmark & Clinical EMR Extraction Lab: ระบบสรุปบทสนทนาเภสัชกรรมด้วยปัญญาประดิษฐ์

ระบบห้องปฏิบัติการทดสอบและประเมินผล (Benchmark & Ablation Lab) สำหรับการถอดเสียงบทสนทนาทางคลินิก (Speech-to-Text) และการสกัดข้อมูลเวชระเบียนการบริบาลทางเภสัชกรรม (Clinical EMR Extraction) พร้อมระบบออกเอกสารเวชระเบียนทางการแพทย์ (PDF) ของระบบ PharmaLog AI: ระบบสรุปบทสนทนาเภสัชกรรมด้วยปัญญาประดิษฐ์

---

## 1. คุณสมบัติหลักของระบบ (Core Capabilities)

### แท็บที่ 1: การถอดเสียงและทดสอบการประมวลผล (Speech-to-Text Benchmark & Ablation)
- **การประมวลผลเสียงแบบคู่ขนาน (Dual-Engine STT):**
  - **Typhoon Realtime (Conformer-Transducer):** ประมวลผลในเครื่องด้วยความเร็วสูงระดับ Realtime (~1-2 วินาที) เหมาะสำหรับงานแบบสด
  - **Typhoon Whisper Large v3:** ประมวลผลขั้นสูงเพื่อความแม่นยำสูงสุด มีการเว้นวรรคคำและจับศัพท์ทางการแพทย์ได้อย่างสมบูรณ์
- **ระบบทดสอบองค์ประกอบย่อยแบบแยกส่วน (Ablation Toggles):**
  - **แก้คำศัพท์ยา (Pharmacy Dictionary):** ระบบตรวจสอบและแก้ไขชื่อยา ขนาดความแรง และหน่วยรับประทานผ่านพจนานุกรมความปลอดภัย พร้อมระบบแก้สระลอยและวรรณยุกต์ภาษาไทย (Unicode Normalizer)
  - **แยกผู้พูด (Speaker Role Separation):** ระบบจำแนกบทบาทระหว่างเภสัชกรและผู้ป่วยจากบริบทคำถาม-คำตอบ
  - **จัดเป็นแชต (Dialogue Turn Formatting):** จัดเรียงบทสนทนาเป็นบับเบิลสลับฝั่งซ้าย-ขวาเพื่อความสะดวกในการตรวจสอบ
- **จัดการคำศัพท์เฉพาะ (Word & Vowel Fixer):** เครื่องมือสำหรับเพิ่มคำศัพท์เฉพาะทางหรือคำที่โมเดลได้ยินคลาดเคลื่อน พร้อมระบบอัปเดตบทสนทนาแบบเรียลไทม์
- **ระบบแคชอัจฉริยะ (Local Pipeline Cache):** บันทึกผลลัพธ์แยกตามขั้นตอน เพื่อให้สลับดูผลกระทบของฟังก์ชันย่อยได้ทันทีโดยไม่ต้องประมวลผลซ้ำ

### แท็บที่ 2: การสกัดเวชระเบียนและการเปรียบเทียบโมเดล (Clinical EMR Extraction & Evaluation)
- **รองรับโมเดลภาษาขนาดใหญ่หลากหลายผู้ให้บริการ (Multi-Provider LLM):**
  - **Groq Cloud:** โมเดลความเร็วสูง เช่น `openai/gpt-oss-120b`, `llama-3.3-70b-versatile`, `qwen/qwen3-32b`, `openai/gpt-oss-20b`
  - **Google Gemini:** โมเดลตระกูล `gemini-2.5-flash`, `gemini-2.0-flash`, `gemini-2.5-pro`
  - **Anthropic Claude:** โมเดลตระกูล `claude-sonnet-4-5`, `claude-3-5-haiku-latest`
- **รองรับแหล่งที่มาของบทสนทนา 3 รูปแบบ:**
  - **ผลถอดเสียง:** ดึงบทสนทนาที่จัดเรียงแล้วจากแท็บที่ 1 โดยตรง
  - **ไฟล์เฉลย (Ground Truth):** ดึงจากคลังเฉลยบทสนทนาจริง 25 เคส เพื่อวัดประสิทธิภาพการสกัดของโมเดลโดยไม่ขึ้นกับความคลาดเคลื่อนของ STT
  - **พิมพ์เอง:** กรอกข้อความบทสนทนาจำลองเพื่อทดสอบกรณีเฉพาะ
- **การประเมินความครบถ้วนทางคลินิก (Clinical Completeness Scoring):**
  - ตรวจวัดหัวข้อเวชระเบียนสำคัญ 5 ด้าน: ประวัติการแพ้ยา, โรคประจำตัว, ประวัติการใช้ยาเดิม, บันทึกทางการแพทย์ (Clinical SOAP), และคำแนะนำจากเภสัชกร/รายการยาที่จ่าย (Plan & Dispensing)
- **ระบบส่งออกเอกสารเวชระเบียนทางการแพทย์ (Clinical EMR PDF Export):**
  - จัดรูปแบบตามมาตรฐานเวชระเบียนผู้ป่วยนอก (OPD Pharmacy Record)
  - ใช้แบบอักษรทางการแพทย์ภาษาไทย **Kanit** (Google Fonts) ขนาดกะทัดรัด คมชัด และจัดวางพอดี 1 หน้ากระดาษ A4
  - มีป้ายกำกับชั้นความลับทางการแพทย์ (Confidentiality Badge), ตารางเมทาดาตา, กล่องคัดกรองความปลอดภัย (เน้นเตือนสีแดงกรณีพบประวัติแพ้ยา), กล่องบันทึก SOAP, กล่องแผนการรักษา, บันทึกบทสนทนา, และส่วนลงนามเภสัชกร

## 2. โครงสร้างไฟล์ในระบบ (Project Directory Structure)

```text
lab/
├── app.py                      # ส่วนติดต่อผู้ใช้หลัก (Streamlit Web Application)
├── pipeline.py                 # เอนจินประมวลผลเสียง ถอดความ แก้สระลอย และจัดบทสนทนา
├── emr_models.py               # เอนจินเชื่อมต่อและเปรียบเทียบโมเดล LLM สำหรับ EMR
├── style.css                   # สไตล์ชีตการจัดรูปแบบหน้าจอ (Custom Design System)
├── custom_dict.json            # ไฟล์บันทึกคำศัพท์เฉพาะทางที่ผู้ใช้กำหนดเอง
├── requirements.txt            # รายการไลบรารีภาษา Python ที่จำเป็น
├── run.sh                      # สคริปต์สำหรับเริ่มการทำงานบน macOS / Linux
├── sample_audio/               # ไฟล์เสียงตัวอย่างบทสนทนาสำหรับทดสอบ
└── modules/
    ├── __init__.py
    ├── emr_groq.py             # โมดูลสกัดเวชระเบียน EMR และโครงสร้าง Prompt มาตรฐาน
    ├── emr_pdf.py              # โมดูลสร้างเอกสารเวชระเบียน PDF ด้วยแบบอักษร Kanit
    ├── pharmacy_dict.py        # โมดูลพจนานุกรมคำศัพท์ยา ตรวจจับหน่วย และแก้สระลอย
    └── pharmacy_data/          # ฐานข้อมูลศัพท์ยาและเฉลยการแก้คำ
        ├── drugs_catalog.json  # บัญชีรายการยาและขนาดยา
        ├── dosage_and_sig.json # รูปแบบวิธีใช้ยาและคำย่อทางการแพทย์
        └── ground_truth_map.json # ตารางเทียบคำผิดและคำถูกจากข้อมูลจริง
```

## 3. ขั้นตอนการติดตั้งและเริ่มต้นใช้งาน (Installation & Setup)

### ขั้นตอนที่ 1: ติดตั้งแพ็กเกจ Python
```bash
pip install -r requirements.txt
```

### ขั้นตอนที่ 2: ตั้งค่า API Keys
ระบบสามารถอ่านคีย์ได้จาก 3 ช่องทางตามลำดับความสะดวก:
1. **กรอกผ่านหน้าจอแอปพลิเคชัน:** สามารถระบุคีย์ในช่องด้านบนของหน้าเว็บ ระบบจะเก็บไว้ในหน่วยความจำชั่วคราว
2. **ไฟล์บันทึกคีย์ในไดเรกทอรีหลักของโปรเจกต์:**
   - `.groq_api_key` สำหรับ Groq API
   - `.gemini_api_key` สำหรับ Google Gemini API
   - `.anthropic_api_key` สำหรับ Claude API
3. **ตัวแปรสภาพแวดล้อม (Environment Variables):**
   ```bash
   export GROQ_API_KEY="gsk_..."
   export GEMINI_API_KEY="AIza..."
   export ANTHROPIC_API_KEY="sk-ant-..."
   ```

### ขั้นตอนที่ 3: เริ่มต้นรันระบบ
สามารถรันได้ด้วยวิธีที่สะดวกที่สุด:

1. **รันผ่านสคริปต์คลิกเดียวที่โฟลเดอร์หลัก (แนะนำ):**
   - บน macOS / Linux: `./run_lab.sh`
   - บน Windows: ดับเบิลคลิก `run_lab.bat`

2. **หรือรันจากภายในโฟลเดอร์ lab/:**
   ```bash
   chmod +x run.sh
   ./run.sh
   ```

3. **หรือรันผ่านคำสั่ง Streamlit โดยตรง:**
   ```bash
   python3 -m streamlit run app.py --server.port 8525
   ```

เปิดเว็บเบราว์เซอร์ไปที่: `http://localhost:8525`

## 4. รายละเอียดโมเดลและการประมวลผล (Technical Specifications)

1. **โมเดลเสียง Typhoon Realtime (Conformer-Transducer):**
   - โค้ดจะอ่านโมเดลจากไฟล์ `models/typhoon-asr-realtime.nemo` ในโฟลเดอร์หลักของโปรเจกต์โดยอัตโนมัติ
   - ถอดเสียงได้อย่างรวดเร็ว เหมาะสำหรับการตอบสนองแบบฉับพลัน
2. **โมเดลเสียง Typhoon Whisper Large v3:**
   - ให้ผลลัพธ์การสะกดคำศัพท์ทางการแพทย์และบริบทภาษาไทยที่แม่นยำสูง
3. **การสร้างเอกสาร PDF (Kanit Typography):**
   - ใช้โมดูล `fpdf2` ร่วมกับชุดแบบอักษร Kanit ที่ติดตั้งอยู่ในโฟลเดอร์ `fonts/`
   - ปรับแต่งระยะบรรทัด (Line Spacing) และขนาดอักษรให้อยู่ในสัดส่วนมาตรฐานเอกสารทางการแพทย์
