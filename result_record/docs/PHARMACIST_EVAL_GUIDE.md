# คู่มือประเมิน AI Feature Extraction (CLO — รายละเอียดสูงสุด)

**วัตถุประสงค์:** ให้เภสัชกรประเมินคุณภาพการ **สกัดฟีเจอร์ (structured fields) จากบทสนทนาโดย AI** (เช่น Gemini) แบบ **สรุปภาพรวม** หลังทบทวนหลายบทสนทนา — **ไม่ระบุไฟล์รายเคสในตาราง**

**ตาราง:** `docs/evaluate_table.csv`  
**สร้างตาราง:** `python evaluation/generate_pharmacist_eval_table.py`

---

## 1. สิ่งที่ระบบให้ AI สกัด (Features)

| ฟีเจอร์ | ความหมาย |
|---------|----------|
| ประเภทการมาใช้บริการ | มาซื้อยา / ปรึกษา / ทั้งคู่ |
| ประวัติการแพ้ยา | ยา กลุ่มยา อาการแพ้ — **ห้ามพลาด** |
| โรคประจำตัว | โรคเดิมที่มีผลต่อการจ่ายยา |
| ประวัติการจ่ายยา | ยาที่ใช้อยู่ / กินมาก่อนมา |
| บันทึกทางการแพทย์ | อาการ ระยะเวลา ความรุนแรง บริบท |
| คำแนะนำจากเภสัช | วิธีใช้ยา ข้อควรระวัง สัญญาณอันตราย |

Pipeline โดยทั่วไป: **เสียง/ข้อความ → ถอดเสียง + แยกผู้พูด → AI สกัด JSON ฟิลด์ด้านบน**

---

## 2. โครงสร้างตาราง

| คอลัมน์ | การใช้ |
|---------|--------|
| **หมวด** | กลุ่มการประเมิน (00–04) |
| **ฟีเจอร์ที่สกัด** | ชื่อฟีเจอร์ หรือ `ทุกฟีเจอร์` / `—` |
| **หัวข้อประเมิน** | หัวข้อย่อยที่ติ๊ก CLO |
| **สิ่งที่พิจารณา** | คำอธิบายเกณฑ์ (อ่านก่อนติ๊ก) |
| **ปรับปรุง … ควรใช้** | ใส่ `1` หรือ `x` **ช่องเดียว** ต่อแถว |
| **หมายเหตุ** | ตัวอย่างที่พบบ่อย ข้อเสนอแนะ |

### หมวดในตาราง

| รหัสหมวด | เนื้อหา | จำนวนแถวโดยประมาณ |
|----------|---------|-------------------|
| `00_ขอบเขต` | ช่วงเวลา จำนวนเคส โมเดล pipeline | 2 |
| `01_ภาพรวม` | คุณภาพการสกัดข้ามฟีเจอร์ | 7 |
| `02_รายฟีเจอร์` | 6 ฟีเจอร์ × (ภาพรวม + 6 เกณฑ์) | 42 |
| `03_Input/Pipeline` | ผลของคุณภาพบทสนทนา/input | 4 |
| `04_สรุปผล` | ความพร้อมใช้งาน ข้อเสนอแนะ | 5 |

---

## 3. ระดับ CLO

| ระดับ | ความหมาย (การสกัดฟีเจอร์) |
|--------|---------------------------|
| **ปรับปรุง** | สกัดผิดบ่อย / อันตราย / ใช้แทนพิมพ์ไม่ได้ |
| **พอใช้** | ช่วยได้บ้าง แต่ต้องแก้หลายฟิลด์ทุกครั้ง |
| **ใช้ได้** | ใช้เป็นฐานได้ ต้องตรวจทุกฟิลด์สำคัญ |
| **ใช้ได้ดี** | ส่วนใหญ่ถูก แก้เล็กน้อย |
| **ควรใช้** | สกัดได้ดี ลดเวลาและความเสี่ยงพิมพ์พลาด |

---

## 4. เกณฑีย่อยต่อฟีเจอร์ (อ่านก่อนติ๊ก)

ใช้กับ **ทุกฟีเจอร์** ใน `02_รายฟีเจอร์`:

1. **ความถูกต้องต่อบทสนทนา** — ตรงสิ่งที่พูด ไม่สลับยา/อาการ  
2. **ความครบถ้วนของประเด็นสำคัญ** — ไม่ขาดหัวข้อที่เภสัชต้องใช้  
3. **ไม่สร้างข้อมูลนอกบทสนทนา** — ไม่ hallucinate  
4. **การจัดการเมื่อไม่มีข้อมูล** — ใช้ `-` ไม่เดา  
5. **ความกระชับและไม่ซ้ำซ้อน**  
6. **ภาษาและศัพท์ทางเภสัช**

### จุดเน้นตามฟีเจอร์

| ฟีเจอร์ | สิ่งที่มักผิด — ให้ดูเป็นพิเศษ |
|---------|-------------------------------|
| ประเภท | สับซน ซื้อยา vs ปรึกษา vs ทั้งคู่ |
| ประวัติการแพ้ยา | **พลาดแพ้ / ไม่บันทึกแพ้ที่พูด / เติมแพ้ที่ไม่มี** |
| โรคประจำตัว | ขาดโรคสำคัญ / เอาอาการมาใส่แทนโรค |
| ประวัติการจ่ายยา | ขาดยาที่กินอยู่ / สับชื่อยา / ขนาดผิด |
| บันทึกทางการแพทย์ | ขาดอาการหลัก ระยะเวลา ความรุนแรง |
| คำแนะนำจากเภสัช | ขาดวิธีใช้/ข้อควรระวัง / **เติมคำแนะนำที่ไม่ได้พูด** |

---

## 5. หมวด 01 — ภาพรวมการสกัด

| หัวข้อ | สิ่งที่พิจารณา |
|--------|----------------|
| ความสอดคล้องข้ามฟีเจอร์ | ยา/อาการ/คำแนะนำไม่ขัดกันระหว่างฟิลด์ |
| การแยกประเด็นลงฟีเจอร์ถูกต้อง | ไม่ใส่ผิดช่อง |
| ความปลอดภัยทางเภสัชกรรมโดยรวม | โดยเฉพาะแพ้ยาและคำเตือน |
| ความสมบูรณ์ของ JSON/โครงสร้าง | ครบทุก key ตามระบบ |
| ความทนทานต่อบทสนทนาซับซ้อน | หลายอาการ หลายยา |
| ความทนทานต่อถอดเสียงไม่สมบูรณ์ | ไม่เดาจนเกิดข้อมูลผิด |

---

## 6. ขั้นตอนแนะนำสำหรับเภสัชกร

1. ทบทวนบทสนทนา + ผล AI ที่สกัดแล้ว **อย่างน้อย 15–30 เคส** (นอกตาราง)  
2. กรอก **00_ขอบเขต** ในหมายเหตุ  
3. ติ๊ก **01_ภาพรวม** จากความรู้สึกรวมหลายเคส  
4. ติ๊ก **02_รายฟีเจอร์** ทีละฟีเจอร์ (แถวภาพรวมฟีเจอร์ + 6 เกณฑ์)  
5. ติ๊ก **03_Input/Pipeline** ถ้ามีปัญหาเสียง/ถอดเสียง  
6. สรุป **04_สรุปผล** และข้อเสนอแนะ  

แถวที่ขึ้นต้น **【คำชี้แจง】** — อ่านอย่างเดียว ไม่ต้องติ๊ก CLO

## 7. หลังประเมิน

ส่ง `docs/evaluate_table.csv` กลับทีมพัฒนาเพื่อ:

- จัดลำดับฟีเจอร์ที่ต้องปรับปรุงก่อน  
- เปรียบเทียบกับคะแนน F1 อัตโนมัติ (ถ้ามี)
